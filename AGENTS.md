# Repository evidence rules

Read `CLAUDE.md` for this project's existing development instructions.

- Before working on a repository, read its entire README and applicable instruction files from scratch in the current task. Do not rely only on previous summaries.
- Inspect the repository's folder and file inventory, then read relevant folder READMEs, configuration, source files, and tests before making claims about behavior or coverage.
- When using another repository as evidence or adapting its code, read that repository's entire README and the relevant implementation files first.
- Treat README feature statements as claims to verify against code and tests, not proof that the feature works.
- Clearly distinguish implemented behavior, passing automated checks, manual verification, untested behavior, known bugs, and plausible failure risks.
- If files or runtime checks are inaccessible, say what could not be verified. Never claim universal application support, installed runtime functionality, or end-to-end performance from build success or isolated unit tests alone.
